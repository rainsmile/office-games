# Office Games — 办公室游戏系统设计

## 概述

一个基于 Web 的线上办公室派对游戏系统，支持 2-6 人远程同时游玩。用户输入昵称即可创建或加入房间，无需登录。战绩通过 localStorage 记录在本地。

## 技术栈

| 层 | 技术 |
|---|------|
| 前端 | Next.js (React) + Tailwind CSS |
| 实时通信 | Socket.IO |
| 音乐 API | Spotify Web API（30 秒预览片段，Client Credentials 认证） |
| 画板 | HTML5 Canvas |
| 战绩存储 | localStorage（绑定随机生成的 playerId） |
| 部署 | Vercel（前端）+ Node.js 服务器（Socket.IO） |

│           │         │              │          │

└─────────────────────┼───────────────────────┘
                      │
┌─────────────────────┼───────────────────────┐
│              Node.js 服务端                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ 房间管理  │ │ 游戏引擎  │ │  Spotify API │ │

游戏状态全部由服务端管理，客户端只负责渲染和发送操作，防作弊且避免状态不一致。

## 房间系统

### 生命周期

1. 房主创建房间 → 生成 6 位房间码（如 `A3F8K2`）
2. 其他人输入昵称 + 房间码加入
3. 房主可踢人、选游戏、开始游戏
4. 所有人离开后房间自动销毁，30 分钟无活动也自动清理

### 房间状态

- `waiting` — 等待中，房主可选游戏、调整设置（回合数、时间限制等）
- `playing` — 游戏进行中
- `result` — 单局结束，展示本局排名，房主可选「再来一局」或「换游戏」

### 玩家身份

- 昵称 + 随机生成的头像颜色（用于区分）
- localStorage 存随机 `playerId`，刷新页面可自动重连同一房间
- 战绩绑定 `playerId`，存在 localStorage 中

### 断线处理

- 断线 10 秒内自动重连，恢复状态
- 超过 10 秒标记为「离线」，游戏跳过该玩家回合
- 玩家可随时重新加入房间恢复

## 游戏设计

### 1. 你画我猜

- 轮流画画，一人画其余人猜
- Canvas 画板（画笔颜色、粗细、橡皮擦、清空）
- 服务端发词给画画的人，其他人在聊天框输入答案
- 答对时间越早分数越高，画的人根据猜对人数得分
- 每轮 60 秒，可配置

### 2. 听歌识曲

- Spotify Web API 获取 30 秒预览片段
- 播放片段前几秒，玩家从 4 个选项中选歌名
- 答对 +10 分，答错不扣分，答越快加分越多
- 支持配置音乐类型（华语流行/欧美/日韩等）

### 3. Emoji 猜词

- 轮流出题，出题者从题库获取一个词，用 emoji 拼出来
- 其他人在聊天框猜，规则同你画我猜
- 题库按难度分级（简单/中等/困难）

### 4. 谁是卧底（最少 4 人）

- 服务端给每人发词，1-2 人拿到不同的词（4-5 人时 1 个卧底，6 人时 2 个卧底）
- 每轮每人用一句话描述自己的词
- 描述完后投票，得票最多的人出局
- 出局后公布身份，卧底全部出局或存活到最后两人时结束

### 5. 抢答题

- 服务端出题（选择题），全员同时看到题目
- 限时 10 秒作答，最快答对的得分最高
- 题库支持多分类（常识/科技/娱乐/脑筋急转弯）

### 6. 排名猜猜猜

- 给出一个主题（如"2024 年票房最高的电影"）和 5 个选项
- 玩家拖拽排序，提交后和正确排名对比
- 每个位置猜对 +5 分，偏差 1 位 +2 分

### 7. 故事接龙

- 服务端给出开头一句话
- 每人限时 30 秒续写一句
- 只能看到上一个人写的最后一句
- 全部轮次结束后公布完整故事，全员投票「最搞笑的一句」，得票最多者加分

## 页面结构

| 页面 | 路径 | 说明 |
|------|------|------|
| 首页/大厅 | `/` | 输入昵称，创建或加入房间，查看个人战绩 |
| 房间等待 | `/room/[code]` | 玩家列表、游戏选择、房主设置、开始按钮 |
| 你画我猜 | `/room/[code]/draw` | Canvas 画板 + 聊天猜词框 + 计分板 |
| 听歌识曲 | `/room/[code]/music` | 播放器 + 四选一选项 |
| Emoji 猜词 | `/room/[code]/emoji` | Emoji 输入区 + 聊天猜词框 |
| 谁是卧底 | `/room/[code]/spy` | 词语显示 + 描述输入 + 投票界面 |
| 抢答题 | `/room/[code]/quiz` | 题目 + 选项按钮 + 倒计时 |
| 排名猜猜猜 | `/room/[code]/rank` | 拖拽排序列表 |
| 故事接龙 | `/room/[code]/story` | 上一句展示 + 输入框 + 最终故事展示 |
| 结算页 | `/room/[code]/result` | 本局排名、积分、返回房间 |

### 通用组件

- 顶部状态栏（房间码、当前游戏、倒计时）
- 玩家头像列表（在线状态、当前分数）
- 聊天/猜词输入框（你画我猜和 Emoji 猜词共用）
- Toast 通知（"某某答对了！"、"某某被投出局"）

### UI 风格

活泼风格：渐变背景、圆角卡片、大 emoji 图标、鲜艳配色，偏游戏感和趣味性。

## 数据模型

### 房间（服务端内存）

```
Room {
  code: "A3F8K2"
  status: "waiting" | "playing" | "result"
  hostId: "player-uuid"
  players: [{
    id: "player-uuid"
    nickname: "小明"
    color: "#ff6b6b"
    score: 0
    online: true
  }]
  currentGame: "draw" | "music" | "emoji" | "spy" | "quiz" | "rank" | "story"
  gameState: { ... }   // 每个游戏各自的状态
  settings: { rounds: 3, timeLimit: 60 }
}
```

## 通信协议（Socket.IO）

| 方向 | 事件 | 说明 |
|------|------|------|
| C→S | `room:create` | 创建房间，传入昵称 |
| C→S | `room:join` | 加入房间，传入昵称+房间码 |
| C→S | `room:start` | 房主开始游戏 |
| S→C | `room:state` | 广播房间完整状态 |
| S→C | `room:player-joined` | 新玩家加入通知 |
| S→C | `room:player-left` | 玩家离开通知 |
| C→S | `game:action` | 玩家游戏操作（画线/选答案/投票等） |
| S→C | `game:state` | 广播游戏状态更新 |
| S→C | `game:event` | 游戏事件（答对了/时间到/回合结束） |
| C→S | `draw:stroke` | 画笔轨迹（高频，单独事件） |
| S→C | `draw:stroke` | 转发画笔轨迹给其他玩家 |

### 设计要点

- 所有游戏逻辑在服务端，客户端只发操作、接收状态
- `game:action` 是通用事件，payload 里用 `type` 区分具体操作
- 画板数据用 `draw:stroke` 单独走，频率高，避免和游戏状态混在一起
- 客户端断线重连后，服务端推一次完整 `room:state` + `game:state` 恢复
